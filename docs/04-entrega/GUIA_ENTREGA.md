# Lista de verificación de entrega — EA2

Completar esta lista cuando el código y las pruebas estén listos.

## Requisitos del proyecto
- [ ] Confirmar que el repositorio es público y que corresponde a la panadería asignada.
- [ ] Confirmar con el docente la composición del equipo: la consigna original indica máximo 3 integrantes y este reparto contempla 4.
- [ ] Completar los datos pendientes en [EQUIPO.md](../01-equipo/EQUIPO.md), sin publicar documentos de identidad completos.
- [ ] Verificar reglas de encendido, potencia contratada, alertas y emergencia.
- [ ] Verificar polimorfismo con método virtual puro, `override` y arreglo de referencias/punteros a `Carga`.
- [ ] UML final coherente con las clases, relaciones y firmas reales del código.
- [ ] Menú, validaciones, simulación, falla con `continue` y emergencia con `break`.
- [ ] Costos con/sin gestor y ahorro calculados sobre periodos equivalentes.
- [ ] Mínimo 6 pruebas ejecutadas con resultados reales y capturas.
- [ ] Compilación sin errores con g++.
- [ ] Cada integrante puede explicar su contribución y cumple los requisitos individuales de commits y video que indique la actividad.
- [ ] Crear la etiqueta `ea2` solo cuando la entrega esté terminada.

## Documentos y evidencias
- [ ] PDF con datos del equipo, UML, constantes, justificación de supuestos, pruebas, capturas y análisis de ahorro.
- [ ] Video individual de máximo 5 minutos, si así lo exige la guía.
- [ ] Enlaces del repositorio y videos incluidos donde solicite la plataforma.
- [ ] Declarar el uso de IA si corresponde a las reglas de la actividad.

> Esta lista orienta la revisión; prevalecen las instrucciones oficiales del instructor. La plantilla del repositorio no es por sí sola el ZIP final de entrega.
